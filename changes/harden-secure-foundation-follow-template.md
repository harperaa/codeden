- **Secure Foundation follows the template's install and dev deploy step by step.** The setup session now goes through the template's `/install` (Phase 1 to Phase 6) and `/deploy-to-dev` (Step 0 to Step 8) in their order, with the template's own commands, and departs from them only where a step needs your own sign-in or browser, would act outside the project folder, or would create something you didn't confirm. Each such place is marked in the session's brief with its reason and listed in the guide ("How the setup follows the template"). Restored: the deploy's own tool and GitHub checks (`check-tools`, `gh-context`), the template's Convex sign-in command and questions, `configure`'s manual steps in the summary, the CI token recorded in `docs/INSTALL.md` after the deploy stores it, and the template's own "Installation Complete!" and "Dev Deployment Complete!" summaries in the session's last message. The deploy's Doppler check now looks in the Doppler project the install created, not one named after the template.
- **The Claude review token is explained as the template's, not CodeHarden's.** The template's install doesn't set `CLAUDE_CODE_OAUTH_TOKEN`, so the setup doesn't either. The session's last message and the project's Secure Foundation setup card now say that the template's Claude review workflows run on GitHub's servers and need that secret, created with `claude setup-token`, that those checks fail on every pull request until it is added, and that reviews inside CodeHarden use your own subscription and need nothing.
- **The deploy's repository owner is remembered, and the form says what it changes.** The owner you pick for a Secure Foundation deploy (your account or one of your organisations, the template's own question from `/deploy-to-dev`) is preselected next time while you still belong to it. Under the owner the form now says that a repository in an organisation gets the secrets that organisation shares, such as a token for the template's Claude reviews, and that a repository under your own account gets none of them.

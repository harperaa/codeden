section: fixed

- **A dev preview installs again when its dependencies are gone.** The app remembered a folder as prepared by its lockfile and the prepare command alone, so a checkout whose installed dependencies had been removed started the dev command straight away and failed with `command not found`. It now also notes what the prepare command put at the top of the folder (`node_modules`, `.venv`; no name is known in advance) and runs the prepare command first whenever one of those is missing, for a session's preview and for the PM thread's alike: **Preparing** with the install's output in the log, then **Starting**, then the link. After this update every preview folder is prepared once more, because the earlier record can't tell whether its install is still there.
- **The suggested dev preview settings include a prepare command.** For a project with a `dev` script the app now suggests the install command for the same lockfile with the dev command: `pnpm install --frozen-lockfile`, `yarn install --frozen-lockfile`, `bun install --frozen-lockfile` or `npm ci`. Both the settings' **Fill it in** and the question the switch at the top of a thread asks show it; without a lockfile only the dev command is suggested, and the question says that there is no prepare command. Both are the app's own fixed texts, never read from the repository, and nothing is stored or run before **Save and allow**.
- **A preview that fails for want of a prepare command says so.** When the dev command ends with exit code 127 or a "command not found" line before anything was listening, and the project has no prepare command, the strip adds that the dependencies probably aren't installed in this checkout, with a link to the project's Dev preview settings. For settings stored without a prepare command, the settings offer the one for the project's lockfile to fill in, stored only with **Save changes…** and **Save and allow**.

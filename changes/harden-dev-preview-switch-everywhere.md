section: changed

- **The dev preview switch is at the top of every thread, off until you switch it on.** Every PM thread and every session of a project now shows the **Dev preview** switch and its status under the header, whether or not the project has dev preview settings yet. Before, a session showed nothing until the project was set up, and the PM thread only a **Set up a dev preview** link. Switching it on in a project that has no settings yet asks **Run these commands on this computer?** with the settings the app can suggest for it (a checkout of this repository, a Secure Foundation project, or a project with a `dev` script), their port variables and where the link comes from; **Save and allow** stores them and starts that thread's preview, **Cancel** stores nothing, and **Edit settings** opens the project's settings instead. Where the app has nothing to suggest, the strip says a dev command is needed first and the switch opens the project's **Settings**, **Dev preview**. Nothing is stored or run without that confirmation on this computer, and the reasons a preview can't run somewhere (another device, no worktree, read-only, sandbox, a stopped session) are shown as before.
- **The PM thread's preview no longer starts by itself.** **On the PM thread** is now off until you switch it on, on the PM thread or in the settings, so saving a project's dev preview settings starts nothing unless you chose that; with it off the settings' button is **Save…**. Projects whose stored settings have it on keep it on: the stored value can't tell a choice from the old default, so it is treated as yours.
